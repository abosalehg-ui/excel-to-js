## ✨ المميزات

- **🔌 أوفلاين بالكامل** — ملف HTML واحد مستقل، لا يحتاج سيرفر ولا إنترنت
- **⚡ 44 دالة مدعومة** — تغطي المنطقية، الرياضية، النصية، التواريخ، البحث، والفحص
- **🧠 Helpers ذكية** — تُولَّد فقط عند الحاجة في رأس الكود الناتج (لا ضخامة زائدة)
- **📐 نطاقات 1D و2D** — `SUM(A1:A10)` تُفرد تلقائياً، `VLOOKUP(A2,B1:D10,3)` تُولَّد كـ matrix
- **🎨 تظليل تركيبي** — تلوين الصيغة أثناء الكتابة مع تحديد موضع الأخطاء بدقة
- **📋 نسخ بزر واحد** — الكود الناتج جاهز للنسخ مباشرة
- **🧮 وضعا إخراج** — باراميتر لكل خلية، أو باراميتر واحد لكل نطاق يستقبل مصفوفة

## 📖 مثال سريع

**الصيغة في Excel:**

```
=IF(MOD(A1, 2) = 0, "زوجي", "فردي")
```

**الكود الناتج:**

```javascript
// دالة محوّلة من صيغة Excel
// المُدخلات المطلوبة: a1
function calculate(a1) {
  return a1 % 2 === 0 ? 'زوجي' : 'فردي';
}
```

**مثال بـ helper مساعد:**

```
=COUNTIF(A1:A5, ">10")
```

```javascript
// ===== Helpers مساعدة =====
function _matchCriteria(value, criteria) {
  /* ... */
}
function _countif(range, criteria) {
  const arr = Array.isArray(range) ? range.flat(Infinity) : [range];
  return arr.filter((v) => _matchCriteria(v, criteria)).length;
}

// ===== الدالة الرئيسية =====
function calculate(a1, a2, a3, a4, a5) {
  return _countif([a1, a2, a3, a4, a5], '>10');
}
```

> الـ Generator يجمع الـ helpers تلقائياً ويرتّبها topologically (التبعيات قبل المعتمدين).

## ⚙️ البنية التقنية

```
Excel Formula Input
       │
       ▼
   Tokenizer  ──►  يقسّم الصيغة إلى رموز (tokens) مع تتبع المواضع
       │
       ▼
    Parser   ──►  يبني شجرة AST بـ Recursive Descent
       │
       ▼
   Generator  ──►  يحوّل الـ AST إلى كود JS
       │              ├─ يتتبع الخلايا المستخدمة
       │              ├─ يفك النطاقات (1D أو 2D حسب الدالة)
       │              └─ يجمع الـ Helpers المطلوبة (topological sort)
       │
       ▼
  JavaScript Output
  ┌─────────────────────────────────┐
  │ // Helpers (لو احتاجت الصيغة)  │
  │ function _vlookup(...) { ... }  │
  │                                 │
  │ // الدالة الرئيسية             │
  │ function calculate(a2, b1, ...) │
  │   return ...;                   │
  │ }                               │
  └─────────────────────────────────┘
```

### وضعا الإخراج

الخلايا تصير باراميترات للدالة المولّدة. الوضع الافتراضي يعطي باراميتراً لكل خلية، وهو
مريح للصيغ الصغيرة لكنه ينهار على النطاقات الكبيرة: `=SUM(A1:A1000)` تولّد توقيعاً
بألف باراميتر. لذلك هناك وضع ثانٍ (مفتاح **«النطاقات كمصفوفات»** فوق لوح الناتج):

| الصيغة                       | الوضع الافتراضي                    | وضع النطاقات           |
| ---------------------------- | ---------------------------------- | ---------------------- |
| `=SUM(A1:A5)`                | `calculate(a1, a2, a3, a4, a5)`    | `calculate(a1_a5)`     |
| `=VLOOKUP(A2,B1:D3,3,FALSE)` | `calculate(a2, b1, b2, b3, c1, …)` | `calculate(a2, b1_d3)` |
| `=SUM(A1:A1000)`             | 1000 باراميتر                      | `calculate(a1_a1000)`  |

في وضع النطاقات يستقبل الباراميتر **مصفوفة ثنائية** دائماً (`[[صف], [صف], …]`)،
والمولّد يفردها تلقائياً في السياقات المسطّحة مثل `SUM`. النطاق المكرّر في الصيغة
يصير باراميتراً واحداً، والكود الناتج يوثّق أبعاد كل نطاق في تعليق فوق التوقيع.

برمجياً: `convertFormula(formula, { rangeParams: true })`.

### قرارات معمارية رئيسية

**نظام Helpers الذكي:** بدل إنشاء مكتبة ثابتة، كل دالة تعلن عن الـ helpers اللي تحتاجها. الـ Generator يتتبع المستخدم فعلاً ويولّد فقط ما يلزم، بترتيب صحيح للتبعيات.

**الفحص النحوي حارس تطوير:** `convertFormula` تُصرّف الناتج بـ`new Function` للتأكد من
صحته نحوياً — لكن هذا يلتقط أخطاء الـGenerator لا أخطاء المستخدم، أي إنه أداة تطوير.
تشغيله في الصفحة كان يفرض `'unsafe-eval'` في الـCSP، فصار يعمل خارج المتصفح فقط
(حزمة الاختبارات في Node تغطّيه كاملاً). للتفعيل يدوياً: `ExcelToJS.SYNTAX_CHECK = true`.

**النطاقات الثنائية:** `VLOOKUP` و`INDEX` تحتاج الجدول كـ `[[r1c1,r1c2],[r2c1,r2c2]]`، بينما `SUM` تحتاجه مسطّحاً. الـ Generator يقرر الشكل حسب `matrixArgs` في تعريف كل دالة.

**التواريخ كـ Date objects:** `DATE(2026,6,15)` تُولَّد كـ `new Date(2026, 5, 15)` مع تعديل الشهر تلقائياً (JS: 0-based). `EDATE` يعالج حالات نهاية الشهر.

**رفض الأعمدة الكاملة:** `B:C` تُرفض برسالة واضحة تقترح البديل (`B1:C100`).

## ⚠️ ملاحظات مهمة

- **الخلايا كمتغيرات:** `A1` تصبح `a1` — القيم تُمرَّر كباراميترات للدالة
- **الأعمدة الكاملة:** `A:B` غير مدعومة، استخدم `A1:B100`
- **حدود الموارد** (تمنع صيغة صغيرة من تجميد المتصفح — معرّفة في `LIMITS` داخل `engine.js`):

  | الحد                             |     القيمة |
  | -------------------------------- | ---------: |
  | طول الصيغة المُدخلة              |  10000 حرف |
  | عمق التداخل                      |   64 مستوى |
  | سلسلة معاملات أحادية / لواحق `%` |         64 |
  | خلايا النطاق الواحد              |       1000 |
  | إجمالي خلايا الصيغة              |       2000 |
  | طول التعبير المولّد              | 200000 حرف |

- **التواريخ:** تُعامَل كـ `Date` objects في JS، ليس كأرقام تسلسلية
- **`%` لاحقة نسبة مئوية** كما في Excel (`50%` = 0.5) — لباقي القسمة استخدم `MOD` (في الإصدارات قبل 3.1.1 كانت `%` تعمل كباقي قسمة ثنائي، وهذا لا يطابق Excel)

### 📐 الانحرافات المعروفة عن Excel

المحوّل يحاكي دلالات Excel بدقة في المقارنات (`=`/`<>` غير حساسة لحالة الأحرف)، والبحث التقريبي في `VLOOKUP`/`HLOOKUP`/`MATCH`، والحدّيات الفارغة (`MIN`/`MAX` → 0، `AVERAGE` → `#DIV/0!`). الفروقات المتبقية الموثقة:

| الحالة                                    | Excel                       | المحوّل                                                  |
| ----------------------------------------- | --------------------------- | -------------------------------------------------------- |
| ترتيب النصوص في `<` / `>`                 | غير حساس للحالة             | حساس للحالة (`<`/`>` في JS)                              |
| نص رقمي داخل نطاق في `SUM`                | يُتجاهل                     | يُجمع (`Number("5")` = 5)                                |
| قيم منطقية داخل نطاق في `SUM`             | تُتجاهل                     | `TRUE` تُحسب 1                                           |
| wildcards في `COUNTIF` (`*`, `?`)         | مدعومة                      | مطابقة حرفية                                             |
| البحث التقريبي في جدول غير مرتب           | نتائج غير معرفة (بحث ثنائي) | مسح كامل يحتفظ بآخر قيمة ≤                               |
| دقة الفاصلة العائمة في `ROUND`            | تقريب عشري داخلي            | حساب IEEE 754 (فروقات نادرة مثل 1.005)                   |
| القسمة على صفر بعامل `/`                  | `#DIV/0!`                   | `Infinity` و`NaN` لـ`0/0` (تلتقطهما `IFERROR`/`ISERROR`) |
| تاريخ في طرف عامل حسابي (مثل `=A1+1`)     | حساب تسلسلي بالأيام         | `Number(Date)` بالمللي ثانية                             |
| `SQRT` لعدد سالب                          | `#NUM!`                     | `NaN` (تلتقطها `IFERROR`/`ISERROR`)                      |
| نص غير منطقي في `AND`/`OR`                | `#VALUE!`                   | صدقية JS — `AND("نص")` = `TRUE`                          |
| معيار `COUNTIF` رقمي مع نص رقمي في النطاق | `"5"` تطابق المعيار `5`     | لا تطابق (مقارنة بنوع JS)                                |
| الأخطاء (`#N/A` وغيرها)                   | نوع خطأ مستقل               | نص عادي تفحصه `_isError`                                 |

> **جديد في 3.1.5 — حالتان خرجتا من الانحراف إلى المطابقة** (رصدهما تقرير متابعة مِحَك
> على 3.1.4):
>
> - **التواريخ النصية `"YYYY-MM-DD"` لا تنزاح مع المنطقة الزمنية**: كانت تمرّ على
>   `new Date` الذي يفسّرها منتصف ليل UTC، فـ`YEAR("2024-01-01")` كانت ترجع `2023`
>   و`DAY("2024-03-10")` ترجع `9` في المناطق غرب غرينتش (نيويورك مثلاً). صارت تُبنى
>   يدوياً بالتوقيت المحلي في `_toDate`، وتشغيلة `TZ=America/New_York` في الـCI تحرسها.
> - **كل العوامل الحسابية على عقد واحد**: ‏3.1.4 أصلحت `+` وحدها فصار `=A1+A2` على
>   فراغين `0` بينما `=A1-A2` عليهما `NaN`. الآن `-` و`*` و`/` و`^` ولاحقة `%`
>   والسالب الأحادي كلها على نفس العقد (الفراغ صفر، غير الرقمي `#VALUE!` يمرّ عبر
>   السلسلة)، والموجب الأحادي محايد كما في Excel يُرجع القيمة كما هي.
>
> **جديد في 3.1.4 — ثلاث حالات خرجت من الانحراف إلى المطابقة** (رصدتها مراجعة
> [`MIHAK_REVIEW_excel-to-js_2026-08-22.md`](MIHAK_REVIEW_excel-to-js_2026-08-22.md)):
>
> - **`+` عملية حسابية لا دمج نصّي**: `=A1+A2` على `"5"` و`"3"` كان يعطي `"53"`
>   وصار يعطي `8`. القيم الجاية من `JSON.parse` أو `<input>` أو عمود CSV تصل نصوصاً،
>   فكانت الأداة ترجّع إجابة خاطئة بلا أي إنذار. والنص غير الرقمي صار `#VALUE!`
>   والخلية الفارغة صفراً كما في Excel. (وفي 3.1.5 عُمّم نفس العقد على بقية العوامل —
>   كانت لا تزال بدلالات JS للفراغ والنص غير الرقمي.)
> - **`TRIM` تطوي المسافات الداخلية**: `" a   b "` كان يعطي `"a   b"` وصار `"a b"` —
>   وهذا غرض `TRIM` الأساسي في Excel، لا مجرد قصّ الأطراف.
> - **`REPLACE` ترفض الوسيط غير الصالح**: `REPLACE("HELLO",-3,2,"X")` كان يعطي `"HXLO"`
>   و`start=0` يعطي `"HELLXELLO"`، وصارا `#VALUE!` — استكمالاً لما شمل
>   `LEFT`/`RIGHT`/`MID` في 3.1.3.
>
> `MOD` و`ROUND` كانتا في هذا الجدول سابقاً وأصبحتا مطابقتين لـExcel:
> `MOD(-3,2)` = `1` (إشارة المقسوم عليه) و`ROUND(-2.5,0)` = `-3` (النصف بعيداً عن الصفر)،
> و`MOD(x,0)` = `#DIV/0!`.
>
> وفي 3.1.3 خرجت ثلاث حالات أخرى من الانحراف إلى المطابقة:
>
> - **الخلية الفارغة نص فارغ**: `=A1&" ر.س"` على خلية فارغة كان يعطي `"undefined ر.س"`
>   وصار يعطي `" ر.س"`. نفس الإصلاح يشمل `CONCATENATE` و`LEN` (كانت ترجع 9) و`TRIM`
>   و`UPPER`/`LOWER` و`LEFT`/`RIGHT`/`MID` و`REPLACE` و`SUBSTITUTE`.
> - **`LEFT`/`RIGHT`/`MID` ترفض الوسيط غير الصالح**: `LEFT(x,-1)` كان يعطي `"hell"`
>   (دلالة `slice` في JS) وصار `#VALUE!` كما في Excel. و`RIGHT(x,0)` تبقى `""`.
> - **`ISNUMBER` تستبعد اللانهاية**: `ISNUMBER(1/0)` كانت `TRUE` وصارت `FALSE`.
